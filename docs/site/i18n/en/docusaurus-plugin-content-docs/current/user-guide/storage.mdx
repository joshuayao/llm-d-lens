---
title: Storage
description: Manage the model cache and shared storage volumes used by deployments.
---

Create a volume on **Storage** before downloading models into it. Use **Model cache**
to manage the downloaded models, not the volume itself.

Storage volumes planned in the cluster wizard appear automatically in **Storage**
once the cluster is finalized. Lens also reconciles finalized clusters that have
a planned storage volume when you open **Storage**, without resurrecting any
volume you explicitly deleted.

## Create a storage volume

1. Open **Storage** and click **New storage volume** beside **Storage volumes**.
2. In **New storage volume**, choose the target **Cluster**.
3. Choose **Type** using the table below, then fill in its connection fields and optional **PVC namespace** (a DNS-1123 label; for **hostPath** and **NFS**, Lens defaults to `lens-storage-<short-id>`, such as `lens-storage-283db094`).
4. To store model downloads, set **Purpose (optional)** to **Model cache** and use **hostPath** or **NFS**.
5. Fill in **Name (optional)** and **Capacity**. A name only has to be unique on the cluster you picked, so each cluster can have its own `a100-model-cache`; reusing a name on the same cluster is rejected, ignoring letter case. Leave the name blank and Lens generates one.
6. If needed, turn **Read-only when mounted** on or off.
7. Click **Create storage volume** and find the new volume in the list.

If your cluster kubeconfig is namespace-scoped and lacks cluster-wide
**Orchestration administrator** permissions to create the PersistentVolume or
PersistentVolumeClaim, Lens presents an **Orchestration administrator setup script**
handoff. When you select an existing namespace where your kubeconfig already has
PVC and Job permissions, the script is PV-only and creates only the cluster-scoped
PersistentVolume; clicking **Re-check** then creates the PVC in that namespace,
verifies binding, and automatically scans existing models. Otherwise (including
the default `lens-storage-<short-id>` namespace), the full setup script also
bootstraps a per-namespace `Role` and `RoleBinding` (`lens-storage-operator`) for
Non-Admin users so your kubeconfig can manage PVCs and model-cache Jobs there. Ask
your **Orchestration administrator**
to run the full setup script on the cluster, then click **Re-check** to verify
the volume is ready and register it in Lens.

| Type | Use it for | Fill in |
| --- | --- | --- |
| **hostPath** | A directory on cluster nodes | **Host path**, **PVC namespace (optional)** |
| **NFS** | A shared network directory | **Server**, **Export path**, **PVC namespace (optional)** |
| **Dynamic PVC** | Storage allocated by a Kubernetes StorageClass; not model-cache downloads | **StorageClass**, **Namespace**, **Access mode** |

Model-cache volumes must be writable; selecting that purpose turns off **Read-only when mounted**.

## Filter the volume list and inspect live status

The filters, volume list and details share one panel. On desktop, a divider
separates the list from the details; on smaller screens, details appear below
the list. The list scrolls within its available space. Pagination appears only
when there are more than 10 matching volumes.

Use the collapse/expand button beside **Storage volumes** to hide or restore
the list. Details fill the panel while the list is hidden. The current volume,
filters and list page are preserved.

1. Open **Storage**.
2. Use **All clusters**, **Search by name**, **All types**, and **All purposes** to narrow the list.
3. Review the summary cards **Total**, **Ready**, **Pending**, **Attention**, and **Failed**.
4. Click a storage volume in the list.
5. In **Status**, review **ID**, **Type**, **Cluster**, **Capacity**, and **Location**.
6. Check the **Persistent Volume Claim** and **Persistent Volume** panels for the live Kubernetes resource state.

On clusters with a namespace-scoped kubeconfig where direct cluster-wide
Kubernetes API reads return `403 Forbidden`, Lens falls back to Prometheus HTTP
queries to observe live PVC/PV status and node drift. If Prometheus metrics are
not yet available for a volume, its resource state shows **Unverified (awaiting
Prometheus)** instead of failing.

## Acknowledge node changes on a hostPath volume

1. Select the storage volume that shows the orange drift warning.
2. Read the warning in **Status**.
3. Click **Acknowledge** to clear the warning after you have verified the node change.

## Delete a storage volume

A volume referenced by one or more deployments shows an **In use** badge and its delete control is disabled; release it from those deployments first.

1. In the volume list, click the delete control titled **Delete storage volume**.
2. In **Delete storage volume**, review the warning about the Kubernetes PVC and PV objects.
3. If the volume has model-cache entries, click **Continue**.
4. On the follow-up **Delete storage volume** step, choose **Keep model files** if you want to keep files on NFS or hostPath, or choose **Delete model files** if you want Lens to remove those files first.
5. If the volume has no model-cache entries, click **Delete storage volume** directly.

If your cluster kubeconfig lacks cluster-wide **Orchestration administrator**
permissions to delete the PersistentVolume or PersistentVolumeClaim, Lens
presents an **Orchestration administrator cleanup script** handoff. When your
kubeconfig has PVC and Job permissions in the target PVC namespace, the script
is PV-only and deletes only the cluster-scoped PersistentVolume(s); ask your
**Orchestration administrator** to run the script on the cluster, then click
**Re-check & Delete** so Lens cleans up model files (if requested) and the PVC
in that namespace and removes the record. If you delete the sole remaining volume
in a Lens-owned `lens-storage-<short-id>` namespace and the namespace is empty,
Lens also cleans up that namespace. If Prometheus is unavailable to confirm
deletion automatically, you can use the manual confirmation fallback after
running the script.

## Model cache

Use [Model cache](/user-guide/model-cache) when you need to manage downloaded model weights themselves. That page covers cache entries and download logs, while **Storage** manages the underlying reusable volumes.

## Permissions

Storage actions are cluster-scoped like the rest of Lens: maintainers can manage volumes only on clusters they are bound to, while admins can manage volumes on every cluster.

On clusters with a namespace-scoped kubeconfig, scanning a volume for existing
models requires `batch/jobs` and `core/pods` permissions in the volume's PVC
namespace; once the **Orchestration administrator** setup script bootstraps
`lens-storage-operator` (or when using an existing namespace where your kubeconfig
already has PVC and Job permissions), automatic and manual model scans run without
further **Orchestration administrator** intervention. If those permissions are
missing, automatic model scans are skipped and manual model-scan requests return
`403 Forbidden`.
