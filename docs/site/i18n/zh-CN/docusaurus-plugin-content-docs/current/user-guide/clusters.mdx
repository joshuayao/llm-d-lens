创建存储和部署模型前，先添加集群。
已有集群使用 kubeconfig 连接；没有集群时，可通过 Kubespray 在准备好的机器上创建。

宽屏下，左侧一列上方为 **Target cluster（目标集群）**及部署快捷操作，
下方为可搜索的 **Clusters（集群）**列表。所选集群的健康状态和编辑按钮保留在选择器旁，
概览显示在右侧。窄屏下，这些面板依次排列在概览上方；集群卡片仍保留各自的操作菜单。

## 开始前：代理排除配置

如果 Kubernetes 组件使用 HTTP(S) 代理，集群内部流量必须绕过代理。
将 `NO_PROXY` 和 `no_proxy` 设为相同值，保留已有排除项，并包含本机回环地址、
节点主机名/IP、API Server 地址、Service/Pod CIDR 和集群 DNS 后缀。
示例（替换占位符；使用自定义集群域名时，相应替换 `cluster.local`）：

```text
localhost,127.0.0.1,::1,<node-hostnames-and-IPs>,<api-server-host>,<service-CIDR>,<pod-CIDR>,.svc,.svc.cluster.local,cluster.local
```

**确认配置在运行中的 `kube-apiserver` 进程上生效**，仅修改 shell 或 Lens 设置不够。
kubeadm 集群在 `/etc/kubernetes/manifests/kube-apiserver.yaml` 中配置环境变量；
kubelet 会重建静态 Pod，期间 API 访问会短暂中断。清单备份应放在该目录之外。
仅配置 CIDR 不能排除以 Service DNS 名发起的请求；缺少域名排除项可能让 webhook
请求经过代理，导致 TLS 错误或超时。

## 从 kubeconfig 注册集群

### kubeconfig 权限

Lens 保留你注册时提供的 kubeconfig。它不会为集群移交创建 ServiceAccount、
ClusterRole、ClusterRoleBinding、替换 kubeconfig 或专用 Lens 身份。编排平台管理员工作
是一次性的 operation 脚本，而不是安装到 Lens 的凭据。

最直接的配置是使用能够执行普通命名空间操作的 edit kubeconfig。某些集群级
operation 可能需要编排平台管理员；Lens 会把它们作为单独的移交展示，而不是要求更宽的
凭据。使用命名空间作用域的 `edit` ServiceAccount kubeconfig 时，Lens 会自动将
默认的 `create-secret` HF token 和移交命名空间对齐到 edit kubeconfig 的可写
命名空间（绝不会覆盖显式自定义命名空间或已有 secret），因此你无需手动修改命名空间。
对于存储卷，Lens 默认将新建 PVC 放入专属的 `lens-storage-<cluster-id>` 命名空间
（`create` 模式，例如 `lens-storage-283db094`）；针对非管理员用户，编排平台管理员
引导脚本会自动在该命名空间中创建 `Role` 和 `RoleBinding`（`lens-storage-operator`），
使 kubeconfig 无需手动配置 RBAC 即可管理其中的 PVC 和模型缓存 Job。

### 配置计划

9 步创建集群向导只保存 provisioning plan，不会在目标集群安装任何内容。
**Review** 是纯净的计划预览（包含监控配置摘要），不包含权限检查。

在 **llm-d stack** 步骤中，你可以按需使用自定义 OCI 容器镜像引用（需包含 `:tag` 或 `@sha256:` 摘要）覆盖 **vLLM image**（`vllmImage`）。留空时，默认镜像来自所选硬件配置文件（`runtime_image`）。镜像预拉取（包括直接管理员执行与编排平台管理员脚本）以及模型部署都会使用该集群镜像，其中单次部署的显式覆盖优先级最高，其次是集群 `vllmImage`，最后是硬件配置文件默认值。

同样在 **llm-d stack** 步骤中，**Monitoring（监控）** 为必填配置，支持两种模式：

- **`managed`（默认）**：安装托管的 `kube-prometheus-stack`（Prometheus、Grafana、
  `kube-state-metrics`、`node-exporter`、Alertmanager 和 Monitoring CRDs）、
  `llm-d` Grafana 仪表盘、集群级 `llm-d-prism-metrics-reader` RBAC，并协同安装
  所选加速器 exporter（由硬件 profile 驱动，例如 NVIDIA DCGM Exporter 或 Intel XPU
  Manager）。可配置 Monitoring 命名空间（默认 `lens-monitoring-<cluster-id>`，例如 `lens-monitoring-283db094`）、可选的
  Prometheus 与 Grafana NodePort（`30000`–`32767`）以及可选的 Monitoring 主机/IP。
- **`existing`**：连接到已有 Prometheus 实例（`prometheusUrl` 必填，`grafanaUrl`
  可选，可配置 Monitoring 命名空间，并提供开关以安装缺失的加速器 exporter 与
  `llm-d-prism-metrics-reader` RBAC）。

点击 **Preflight** 会打开 **Execute** 步骤并在那里先运行权限检查，评估
edit kubeconfig 并拆分为：

- **User operations**：Lens 使用你的 kubeconfig 执行。
- **编排平台管理员 operations**：Lens 不执行；你把生成的脚本发给编排平台管理员。
- **Lens operations**：本地后续工作，例如 gateway exposure 或 model cache
  job fan-out。Lens 在 **Complete** 时执行。
- **Blocked operations**：缺少所需 kubeconfig 权限的用户自有 secret 操作或
  Lens operation。请授予所需访问权限或调整计划后重新检查；这些操作绝不交给
  编排平台管理员。

在 **Model Cache** 步骤中保存新的 Hugging Face token 时，Lens 会将其加密并
临时存储在 draft 中，绝不会写入 provisioning plan 或编排平台管理员移交脚本，也不会以
明文形式返回展示。之后恢复 draft 时（即使关闭浏览器或切换标签页），向导也会
保留已保存状态（`Saved for this draft`），支持无需重新输入 token 即可继续
**Preflight** 和 **Execute**，需要时也可替换；一旦集群完成或被丢弃，该临时
draft 副本会自动删除。

### 运行 Preflight

**Review** 是纯净的计划预览，不包含权限检查。Preflight 需要已保存
计划和 Hugging Face token；点击 **Preflight** 会直接打开 **Execute** 步骤并在该步骤中
先运行权限检查，在需要时加载或生成编排平台管理员脚本。它不会自动启动任何 user operation。恢复 draft 到 Review
时也不会自动检查，仍需显式运行 Preflight。

- **Ready**：权限检查通过后，点击 **Execute** 开始执行 user operations。具备完整集群权限（等效于 `cluster-admin`）的 kubeconfig 会直接以 **Ready** 通过预检，无需生成编排平台管理员移交脚本，也无需 **Waiting for marker** 步骤——一旦集群级通配符 SSAR 检查通过，Lens 会在 **Execute** 阶段自动执行所有安装操作（包括命名空间创建、来自 chart 的 CRD 如 `lws.crds`，以及由 profile 驱动的远端 Kustomize overlay 如 NFD 或非 DRA 设备插件）。
- **Orchestration administrator operations**：Execute 显示脚本和
  **Re-check**。在重新检查验证 marker、提供 token 且没有剩余 admin operation
  前，user operation 保持禁用；验证通过后点击 **Execute** 开始执行。
- **Blocked**：Execute 显示需要你修复的用户访问问题，并保持 user 执行禁用。

### 编排平台管理员移交

当拆分包含 orchestration administrator operations 时，Lens 会显示：

1. 编排平台管理员 operation 列表和 readiness 检查（位于 **View operation details** 下）。
2. 可下载的幂等编排平台管理员脚本。
3. **Re-check** 操作，用于重新检查权限并验证编排平台管理员完成状态。

把脚本发给编排平台管理员。编排平台管理员用自己的凭据运行一次。脚本只包含计划的
orchestration administrator operations，不包含你的 kubeconfig、Lens 身份或 secret 值。所有
orchestration administrator operation 及其 readiness 检查通过后，脚本写入完成 marker，并自动
写入为 `managed` 监控分配的 `prometheusNodePort`、`grafanaNodePort` 与
`monitoringHost`。

编排平台管理员完成后，在 Lens 选择 **Re-check**。Lens 会重新检查权限、读取 marker、
把 orchestration administrator operations 记录为完成、自动发现并持久化监控端点且探测 Prometheus
健康状态（无需手动输入端口），并在完成后获取 execution token。在此之前
user operations 保持禁用。如果 marker 缺失、部分、过期或不可读，Lens 会说明剩余
orchestration administrator operations，不会启动 user run。

对于部分权限 kubeconfig，当任何 operation 缺少权限（或需要集群级通配符检查）时，Lens 会自动将其未完成的上游依赖（不包括用户自有 secret 和 Lens 侧验证步骤）提升到编排平台管理员脚本中，确保前置条件按顺序清晰执行。

使用 **具备完整集群权限的 kubeconfig** 时，Lens 会直接执行监控与加速器 exporter 安装、发现
NodePort 端点、持久化派生 URL，并在 **Complete** 阶段验证 Prometheus 就绪状态。
使用 **部分权限（`edit`）kubeconfig** 时，自包含的监控与 exporter 安装脚本会包含在
单个可下载的编排平台管理员脚本中。

### 执行 user operations

Preflight 打开 **Execute** 且权限检查通过（或编排平台管理员移交验证完成）后，点击 **Execute** 即可按依赖顺序执行 user operations，执行开始后会显示 **Setup progress**。每个 operation 可能有 readiness wait；
wait 失败会停止运行，但不会把 operation 标记为完成。恢复执行时已记录的
operation 会被跳过。

execution token 由 handoff verification 或第一个 user operation 创建；后续
operation 复用该 token。计划变更会使旧 run 过期，并要求重新检查拆分。

**403** 表示 Kubernetes 在预检后拒绝了 operation。Lens 会刷新拆分，把该
operation 加入编排平台管理员移交，同时保留已完成的 user operations。**401** 表示
kubeconfig 无效或过期。**504** 表示 operation 已应用但未就绪，应在集群资源
稳定后重试。其他错误会指出失败的 operation，并保留已完成工作。

### Complete

**Complete** 执行剩余的 Lens 本地 operation，确认每个 operation 都是
user-done、administrator-done 或 Lens-done，并在一步中 finalize 集群。集群随后
离开 draft 状态。如果 Lens operation 失败——包括 **403** 权限拒绝（同时会刷新
权限检查）——execution token 会保留，便于你修复权限并重试 Complete。

### 从 M5 之前的 step 流程升级

M5 之前的 draft 使用独立的 step ledger，该 ledger 不会迁移。请重新打开
draft，运行 **Preflight**，然后再次执行 operation 列表。仅有完成
时间戳不足以视为完成；只有完成记录的 plan hash 与当前计划一致才算完成。

### 凭据轮换是独立操作

不要在权限移交面板上传替换 kubeconfig。kubeconfig 替换是独立的集群设置操作，
仅用于凭据轮换。它不会重新运行权限检查，也不会更改 provisioning plan。

## 通过 Kubespray 创建新集群

1. 打开 **Clusters → Add**，填写集群名称。
2. 选择 **Bootstrap a new cluster via Kubespray（通过 Kubespray 创建新集群）**。
3. 为每台机器填写 **Host(s)**、**Port**、**Role(s)**、**Username**，并提供 SSH 私钥或密码。点击 **Add node** 添加更多机器。
4. **Network proxy for target nodes** 保持 **Auto** 可沿用各机器的代理；需要指定时选择 **Custom for these nodes**。
5. 点击 **Run preflight（运行预检）**，修正失败项并重新检查，直到全部主机通过。
6. 点击 **Start bootstrap（开始创建）**，查看执行进度。
7. 生成的 kubeconfig 出现后，按上面的注册步骤继续，直到 **Complete** 和 **Done**。

此操作会修改目标机器。开始前请确认主机地址和节点角色。

## 修改集群设置

1. 选择集群，点击 **Edit cluster（编辑集群）**。
2. 修改名称、描述、代理、**HF_TOKEN secret**、**vLLM image**（`vllmImage`，或重置为空以使用所选硬件配置文件的 `runtime_image` 默认值）、模型网关设置或监控设置（**Monitoring mode（监控模式）**：`Managed` 或 `Existing`；在 `Existing` 模式下可配置外部 **Prometheus URL** 与可选 **Grafana URL**；在 `Managed` 模式下，端点和 NodePort 会自动发现并以只读方式展示）。
3. 点击 **Save changes（保存更改）**，确认新值已显示。

组件版本由 Lens 发布版本提供，不能在此处修改。

### 轮换 HF_TOKEN secret

**HF_TOKEN secret** 保存该集群拉取受限模型所用的 Hugging Face 令牌。
Lens 只记录该 Secret 的命名空间和名称；令牌值保存在集群上，不会再次显示。

1. **New token（新令牌）**留空表示保留当前令牌。只有需要替换时才填写。
2. 只有在需要让集群指向另一个 Secret 时，才修改 **Namespace（命名空间）**或 **Secret name（Secret 名称）**；该 Secret 不存在时 Lens 会创建它。
3. 点击 **Save changes（保存更改）**，确认提示中显示的是写入的 Secret。

部署和模型缓存下载在运行时会把令牌复制到各自的命名空间，
因此已在运行的工作负载在重建之前仍使用旧令牌。

## 检查模型网关访问

1. 在 **Clusters → Edit cluster** 中检查 **Gateway host/IP** 和 **Gateway exposed port**，确认它们是客户端可访问的地址。
2. 打开 **Model services（模型服务）**，找到该集群的 **Gateway** 节点。
3. 打开节点菜单：未安装时选择 **Install（安装）**；需要应用已保存设置时选择 **Reconcile（协调）**。
4. 查看操作日志，然后[发布模型服务并发送请求](/tutorials/publish-a-model-service)。

安装或请求失败时，参阅[故障排查](/troubleshooting)。
创建和编辑向导当前提供 **Istio**；其他提供方的手动修复操作不属于正常注册步骤。

## 查看集群健康状态

页面可见时，集群列表每五秒静默刷新；当前集群的健康数据每五秒更新，
其他集群的健康数据每十秒更新，无需手动刷新。列表刷新保留当前选择和搜索条件；
更新失败时保留已有条目并显示错误信息。

1. 在 **Clusters** 中选择集群。
2. 检查 **Workers**、**CPU**、**Memory**、**Deployable GPU**、**VRAM**、**Disk** 和 **Monitoring**。
   **Memory** 和 **Disk** 主数值显示的是集群总容量中仍然空闲的部分，已使用的百分比
   显示在下方的 **Usage** 一行。显示为短横线表示该集群当前无法上报该读数，而不是
   剩余为零。

Clusters 页面仅展示基础设施健康状态和工作节点，不再显示部署列表，也不将单个部署失败计入集群健康状态。
点击 **Target cluster** 面板中 **Deploy a model** 下方的 **Deployments** 按钮，
即可打开独立的 [Deployments 页面](/user-guide/deployments)，
并自动将当前集群填入过滤器。过滤器仍可更改或清除；入口 URL 会保留该集群，刷新后仍可恢复。
在该页面管理部署、端点和日志。
部署监控和性能分析仍可通过[可观测性页面](/user-guide/observability)使用。

点击 **Deployments** 下方的 **Model services** 按钮，可打开
[模型服务页面](/user-guide/model-services)，并在服务拓扑过滤器中自动选中当前集群。
该过滤器同样可以更改或清除；刷新页面或使用浏览器前进、后退时，入口 URL 会恢复集群条件。

配置监控后，Lens 会直接通过 HTTP 从 Prometheus 获取实时节点、CPU、内存、磁盘和加速器遥测数据，
支持无集群级 `nodes` RBAC 权限的受限命名空间作用域 kubeconfig。

**Monitoring（监控）**健康卡片在编排平台管理员与非管理员 kubeconfig 以及 `managed` 和 `existing`
两种监控模式下均与[可观测性页面](/user-guide/observability)保持一致：

- **编排平台管理员 + `managed` 模式**：直接验证 Kubernetes 监控栈。
- **非管理员 kubeconfig 与 `existing` 模式**：探测已配置的 Prometheus 和 Grafana HTTP 端点，
  仅统计适用组件（`existing` 模式下可选的 Grafana 以及纯 CPU 集群上的加速器 exporter
  不计入必需数量）。

点击 **Monitoring** 卡片可直接跳转至[可观测性页面](/user-guide/observability)。当监控处于降级、
不可达或未配置状态时，概览横幅会根据角色与模式提供对应指引：

- **编排平台管理员（`managed`）**：在 **Observability** 中安装或重新安装监控栈。
- **编排平台管理员（`existing`）**：在 **Clusters（集群）**页面通过 **Edit cluster（编辑集群）**配置外部 Prometheus 和可选的 Grafana URL，然后在 **Observability** 中点击 **Re-check（重新检查）**。
- **非管理员**：在 **Clusters（集群）**页面通过 **Edit cluster（编辑集群）**配置外部 Prometheus 和 Grafana URL，或在 **Observability** 中点击 **Install（安装）** / **Reinstall（重装）**运行**编排平台管理员**配置或修复脚本，然后点击 **Re-check（重新检查）**。

## 设置节点维护模式

1. 在集群的 **Workers** 列表中选中节点。
2. 点击 **Enter maintenance mode（进入维护模式）**，核对节点名称，再点击 **Cordon nodes**。
3. 维护结束后选中节点，点击 **Exit maintenance mode（退出维护模式）**，再确认 **Uncordon nodes**。

**进入维护模式只阻止新 Pod 调度，不会停止或迁移已有 Pod。**
需要停机或迁移负载时，请另行安排。

## 删除集群注册

1. 打开集群的 **Actions → Delete cluster（操作 → 删除集群）**。
2. 核对集群名称和删除警告。
3. 点击 **Delete（删除）**。
   - 如果当前 kubeconfig 有权限删除所有 Lens 自有资源，Lens 会直接清理这些资源并移除注册记录。
   - 如果命名空间级的 `edit` kubeconfig 无法删除集群级或跨命名空间资源（或集群不可达），弹窗会切换为 **Orchestration administrator cleanup required（需要编排平台管理员清理）**（离线时显示 **Cluster unreachable（集群不可达）**）。
4. 当出现 **Orchestration administrator cleanup required（需要编排平台管理员清理）** 或 **Cluster unreachable（集群不可达）** 时：
   - 复制或下载幂等清理脚本，交给编排平台管理员执行。
   - 编排平台管理员执行完成后，点击 **Re-check & Delete（重新检查并删除）**（集群不可达时为 **Retry & Delete（重试并删除）**）以验证完成标记并移除注册记录。
   - 如果无法自动验证完成标记（`unconfirmed`）或集群不可达，勾选显式确认框并点击 **Confirm & Delete Record（确认并删除记录）** 以从 Lens 中移除注册记录。

Lens 永远不会删除 `existing-secret:*` Secret、已有或共享命名空间（包括 `existing` 模式的 Gateway 或 Secret 命名空间）、裸 `lens-storage`、裸 `lens-monitoring` 或遗留的 `llm-d-bench-storage` 命名空间，以及受保护的系统命名空间（`default`、`kube-system`、`kube-public`、`kube-node-lease`、`istio-system`、`envoy-gateway-system`、`envoy-ai-gateway-system`、`agentgateway-system`）。由 Lens 创建的集群专属 `lens-storage-<cluster-id>` 以及 `managed` 模式下创建的 `lens-monitoring-<cluster-id>` 命名空间（未与其他集群共享时）可在清理时删除。删除启用 `managed` 监控的集群时，Lens 会清理托管的监控与加速器 exporter 资源（必要时通过两阶段编排平台管理员清理流程执行，同时保留同一 Kubernetes API Server 上与其他集群共享的资源）；在 `existing` 监控模式下，Lens 永远不会删除监控资源。对于仍在注册过程中的集群，向导期间创建的存储卷会连同其 PVC 和 PV 一起删除，而 NFS 或 hostPath 上的模型文件会保留。已完成注册且仍存在部署或存储卷的集群必须先删除这些资源才能删除。

## 看不到集群

请管理员检查你的集群分配。维护者管理已分配的集群，管理员可以管理所有集群。
